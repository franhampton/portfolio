# Maps – Automized current-state process maps

Baseline: the client-approved "Reporting and Analytics – Sales and Operations Reporting" map. Every new map must look and behave like it. Standards come from the team's process-map review plus Fran's later edits.

## Workflow

1. **Find the sources.** Get the process name and the client. Locate the interview transcripts (usually SharePoint: `3. Clients/<Client>/01. Digital Operations Assessment/2. Client Reference Materials/3. Interview Transcripts`) and any prior playbook or map for that process. Ask if unclear.
2. **Extract from transcripts only.** Every task, bullet, pain point, lane, icon and software label must trace to something a client interviewee said (not an Automized interviewer). Record speaker plus timestamp for each item as you go. For long transcript sets, split them across parallel subagents.
3. **Build a spec JSON** (format below) and render it with `render_map.py` (code below). Write the script to disk, run `python3 render_map.py spec.json out.html`, then screenshot the result with Playwright and look at it before delivering.
4. **Freeze the swimlane titles.** As the last build step (after `combine_tabs.py` for multi-tab maps), run `python3 add_sticky_lanes.py in.html out.html` (code below) so the blue lane titles stay fixed on the left while the map scrolls right. Test it: in Playwright, set `.map` scrollLeft to a few hundred px on each tab and screenshot; the lane names must stay pinned and line up with their rows.
5. **Cross-check before delivering.** Re-read every transcript against the finished map and report to the user, grouped as: Incorrect, Goes beyond what was said, Sticky notes the transcripts answer, Missing (in scope), Probably other maps. Quote speaker and timestamp. Do not silently change anything. Let the user decide.
6. **Deliver.** Save to the user's Downloads (or the folder they name), and to SharePoint `.../4. Deliverables/Process Maps` when asked. Save a cross-check notes doc plus the spec JSON to the client's project.

## Content rules

- **Lanes are job positions only.** Never software or systems. Use the title the client uses. If no one stated a title, add a lane sticky saying "Confirm job titles".
- **Names never appear in task or bullet text.** The lane defines who does the task. Software is never named in the task text either; it goes in the label above the box.
- **Objective only.** Show the current process with no judgments, assessments or "fix first" calls. No hot-spot badges.
- **Pain points come straight from a client interviewee.** Check the context: if the speaker framed it as positive or was talking about someone else, it is not a pain point for that lane.
- **Frequency is not stated per step.** It belongs at the map or process level. No "daily/weekly" chips. Avoid time words in bullets unless they are essential facts.
- **Bullets:** a maximum of 3 per step, short and simple. Pain points sit under the bullets and do not count toward the 3.
- **Report and file names:** bold, with the extension, like **Labor Tracker.xls**. If the actual file name wasn't stated, add a sticky: "Confirm the file names…".
- **Icons (BPMN style):** person = user task (someone works in a system); hand = manual task (done by hand, rekeying, Excel built by hand, meetings); script = automated or scheduled. Only one icon per task.
- **Unconfirmed items get a yellow TO CONFIRM sticky** instead of a guess. Examples: who owns a step, which software, whether something is scheduled or manual, what a report is called.
- **START and END:** bold START at the top of the first task box and bold END at the bottom of the last. No separate circles.
- **Don't invent steps.** Never create a step no one described, such as a generic "Receive reports". If a step has nothing stated, leave it out or ask.
- **Arrow order is a layout choice.** If asked, explain that only some arrows are real handoffs.
- **Scope:** keep items that belong on other process maps (billing, AP, inventory, sales management) off this map. List them for the user instead.

## Visual standard (built into render_map.py; don't change without being asked)

- **Header:** client logo, title in Playfair Display, subtitle, yellow (#FCD818) rule underneath. Legend box on the right titled LEGEND, listing User task, Manual task and Automated (script) stacked vertically. Nothing else in the legend.
- **Lanes:** horizontal, with blue (#004890) label blocks, large white bold text and no icons. Alternating white and cream rows. Each lane's height fits its own content.
- **Frozen lane titles:** the blue lane title column stays fixed on the left when the map scrolls horizontally (added by `add_sticky_lanes.py`). It only shows when the map is wider than the window. Content and layout are unchanged.
- **Task boxes:** 176 x ~122 with rounded corners. Title is centered horizontally and vertically. The icon sits top-left.
- **Software label:** bold blue monospace text above the box. Separate multiple tools with " | ".
- **Step detail:** a single left square bracket under each task, the same width as the task box, with left-aligned bullets.
- **Pain points:** red italic text under the bracket, no box and no bullet, prefixed with bold "Pain Point:".
- **Sticky notes:** straight (never rotated), yellow, with a "TO CONFIRM" header. Place them beside the step in an empty column (`note_side` right or left) so they never overlap a step or arrow.
- **Arrows:** thick (2.6), with rounded bends. The vertical run goes in the gap between columns so the arrowhead has a straight lead-in.
- **File size:** the logo is embedded as a small JPEG (~160x80) to keep the file small. This matters for SharePoint upload, because the connector takes inline text only, about 35KB.

## Spec format

```json
{
 "client": "Sample Client",
 "title": "Reporting and Analytics",
 "subtitle": "Sales and Operations Reporting",
 "logo": "logo.jpg",
 "lanes": ["Inventory & Purchasing Mgr", "IT Lead", "Sales Support", "CFO", "VP Operations", "General Managers"],
 "lane_note": "Confirm job titles",
 "steps": [
  {"lane": "Inventory & Purchasing Mgr", "kind": "script", "software": "Reporting tool",
   "title": "Send saved reports by email",
   "bullets": ["At least 100 saved reports", "Run daily, weekly and monthly"],
   "pains": ["reports often go unread at store level"]},
  {"lane": "Inventory & Purchasing Mgr", "kind": "manual", "software": "Reporting tool | POS | Tracking app",
   "title": "Re-key report data into spreadsheets",
   "bullets": ["**New Tire Sales by Brand.xls** – emailed daily to President and VP Sales"],
   "note": "Confirm the file names of the Excel sheets.", "note_side": "right"}
 ]
}
```

- **`kind`:** one of user, manual or script.
- **`**...**`:** marks bold text in bullets.
- **`pains`:** plain text; the "Pain Point:" prefix is added automatically.
- **Order:** steps render left to right in list order.
- **Logo:** an image path, or a data: URI. Pull the client logo from their existing playbook or deliverables.
- **Full baseline spec:** the client project keeps the complete example spec and the script at `claude/maps/`.

## render_map.py

```python
#!/usr/bin/env python3
"""Automized swimlane process map renderer (Maps skill).
Usage: python3 render_map.py spec.json out.html
"""
import html, json, re, sys, base64, io, os

spec = json.load(open(sys.argv[1])); OUT = sys.argv[2]
BLUE = "#004890"; INK = "#1C1F24"; CREAM = "#F4F2EE"; LINE = "#DAD6CE"; ARROW = "#3A3F46"
LANES = spec["lanes"]
LANE_W, COL_W, BOX_W = 190, 244, 176
TASK_W = BOX_W; PAD_X = (COL_W - BOX_W) / 2
SW_H, LANE_PAD = 30, 16
TITLE_FS, BUL_FS, TITLE_LH, BUL_LH = 15, 12, 19, 16
CH_TITLE, CH_BUL, CH_PAIN = 19, 25, 29

def wrap_words(words, maxc):
    lines, cur, n = [], [], 0
    for w, st in words:
        add = len(w) + (1 if cur else 0)
        if cur and n + add > maxc:
            lines.append(cur); cur, n = [], 0; add = len(w)
        cur.append((w, st)); n += add
    if cur: lines.append(cur)
    return lines

def parse_bold(text):
    segs = []
    for k, part in enumerate(re.split(r"\*\*", text)):
        if part: segs.append((part, "b" if k % 2 else "n"))
    return segs

def seg_words(segs):
    out = []
    for text, st in segs:
        for w in text.split(" "):
            if w: out.append((w, st))
    return out

STEPS = []
for i, s in enumerate(spec["steps"]):
    st = dict(s)
    st["li"] = LANES.index(s["lane"])
    st["tlines"] = wrap_words([(w, "t") for w in s["title"].split()], CH_TITLE)
    st["blines"] = []
    for b in s.get("bullets", []):
        for k, l in enumerate(wrap_words(seg_words(parse_bold(b)), CH_BUL)):
            st["blines"].append((k == 0, l))
    st["plines"] = []
    for p in s.get("pains", []):
        words = [("Pain", "pb"), ("Point:", "pb")] + [(w, "i") for w in (p[0].upper() + p[1:]).split()]
        for k, l in enumerate(wrap_words(words, CH_PAIN)):
            st["plines"].append((k == 0, l))
    st["start"] = i == 0; st["end"] = i == len(spec["steps"]) - 1
    STEPS.append(st)

TASK_H = max(len(s["tlines"]) for s in STEPS) * TITLE_LH + 2 * 42
DET_GAP = 10
def ann_h(s): return (len(s["blines"]) * BUL_LH + 10) if s["blines"] else -8
def pain_h(s): return (len(s["plines"]) * BUL_LH + 6) if s["plines"] else 0
def det_h(s): return ann_h(s) + (8 + pain_h(s) if s["plines"] else 0)
LANE_HS = [max(SW_H + TASK_H + DET_GAP + max([det_h(s) for s in STEPS if s["li"] == k] or [0]) + 2 * LANE_PAD, 230) for k in range(len(LANES))]
LANE_Y = [sum(LANE_HS[:k]) for k in range(len(LANES))]
W = LANE_W + COL_W * len(STEPS) + 20; H = sum(LANE_HS)
def box_xy(i, s): return LANE_W + i * COL_W + PAD_X, LANE_Y[s["li"]] + LANE_PAD + SW_H

def icon(kind, x, y, c=BLUE):
    if kind == "user":
        return (f'<g transform="translate({x},{y})" fill="none" stroke="{c}" stroke-width="1.7"><circle cx="11" cy="7" r="5"/>'
                f'<path d="M2 22 Q2 13 11 13 Q20 13 20 22 Z" fill="{c}" fill-opacity=".15"/></g>')
    if kind == "manual":
        return (f'<g transform="translate({x},{y})" fill="{c}" fill-opacity=".12" stroke="{c}" stroke-width="1.6" stroke-linejoin="round" stroke-linecap="round">'
                f'<path d="M6 21 L3 13 Q2.5 11 4.5 11 Q6 11 6.8 13 L7.5 15 L7.5 4 Q7.5 2.5 9 2.5 Q10.5 2.5 10.5 4 L10.5 10 L10.5 2.5 Q10.5 1 12 1 Q13.5 1 13.5 2.5 L13.5 10 L13.5 3.5 Q13.5 2 15 2 Q16.5 2 16.5 3.5 L16.5 10.5 L16.5 6 Q16.5 4.5 18 4.5 Q19.5 4.5 19.5 6 L19.5 15 Q19.5 21 15 21 Z"/></g>')
    return (f'<g transform="translate({x},{y})" fill="none" stroke="{c}" stroke-width="1.6" stroke-linejoin="round" stroke-linecap="round">'
            f'<path d="M5 2 H19 Q16 6 19 11 Q22 16 19 21 H5 Q8 16 5 11 Q2 6 5 2 Z" fill="{c}" fill-opacity=".12"/><path d="M8 7 H15 M8.5 11 H16 M8 15 H15"/></g>')

def runs(words, attrmap):
    out, cur, buf = [], None, []
    for k, (w, st) in enumerate(words):
        t = (" " if k else "") + w
        if st == cur: buf.append(t)
        else:
            if buf: out.append((cur, "".join(buf)))
            cur, buf = st, [t]
    if buf: out.append((cur, "".join(buf)))
    return "".join(f'<tspan{attrmap[st]}>{html.escape(t)}</tspan>' if attrmap.get(st) else html.escape(t) for st, t in out)

def tline(x, y, words, cls, anchor="middle"):
    a = ' text-anchor="middle"' if anchor == "middle" else ""
    return f'<text class="{cls}" x="{x:g}" y="{y:g}"{a}>{runs(words, {"b": " font-weight=\"700\""})}</text>'

o = []; e = o.append
e(f'<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 {W:g} {H:g}" width="{W:g}" role="img" aria-label="Swimlane process map: {html.escape(spec["title"])}">')
e('<defs>' + "".join(f'<g id="i-{k}">{icon(k, 0, 0)}</g>' for k in ("user", "manual", "script")) +
  f'<marker id="ah" markerWidth="5" markerHeight="5" refX="8" refY="5" viewBox="0 0 10 10" orient="auto" markerUnits="strokeWidth"><path d="M0 0L10 5L0 10z" fill="{ARROW}"/></marker></defs>')
for li, name in enumerate(LANES):
    y, lh_ = LANE_Y[li], LANE_HS[li]
    e(f'<rect x="0" y="{y:g}" width="{W:g}" height="{lh_:g}" fill="{"#fff" if li % 2 == 0 else CREAM}" stroke="{LINE}"/>')
    e(f'<rect x="0" y="{y:g}" width="{LANE_W}" height="{lh_:g}" fill="{BLUE}" stroke="{LINE}"/>')
    ws = wrap_words([(w, "t") for w in name.split()], 14)
    y0 = y + lh_ / 2 - (len(ws) - 1) * 11
    for k, l in enumerate(ws):
        e(f'<text class="lane" x="{LANE_W/2:g}" y="{y0 + k*22:g}" text-anchor="middle">{html.escape(" ".join(w for w, _ in l))}</text>')

for i, s in enumerate(STEPS):
    x, y = box_xy(i, s); cx = x + BOX_W / 2
    if s.get("software"):
        e(f'<text class="sw" x="{cx:g}" y="{y - SW_H/2 - 2:g}" text-anchor="middle">{html.escape(s["software"])}</text>')
    e(f'<rect x="{x:g}" y="{y:g}" width="{TASK_W}" height="{TASK_H}" rx="10" fill="#fff" stroke="{INK}" stroke-width="1.3"/>')
    e(f'<use href="#i-{s["kind"]}" x="{x + 8:g}" y="{y + 8:g}"/>')
    if s["start"]: e(f'<text class="se" x="{cx:g}" y="{y + 20:g}" text-anchor="middle">START</text>')
    if s["end"]: e(f'<text class="se" x="{cx:g}" y="{y + TASK_H - 18:g}" text-anchor="middle">END</text>')
    ty = y + TASK_H / 2 - (len(s["tlines"]) - 1) * TITLE_LH / 2 + (10 if s["start"] else 0) - (10 if s["end"] else 0)
    for l in s["tlines"]:
        e(tline(cx, ty, l, "task")); ty += TITLE_LH
    dy = y + TASK_H + DET_GAP; ah = ann_h(s)
    if s["blines"]:
        e(f'<path d="M {x + 9:g} {dy:g} H {x + 1:g} V {dy + ah:g} H {x + 9:g}" fill="none" stroke="#52565C" stroke-width="1.6"/>')
    by = dy + 5 + BUL_LH / 2
    for first, l in s["blines"]:
        if first: e(f'<text class="bul" x="{x + 13:g}" y="{by:g}">•</text>')
        e(tline(x + 24, by, l, "bul", "start")); by += BUL_LH
    if s["plines"]:
        by = dy + ah + 8 + BUL_LH / 2; started = False
        for first, l in s["plines"]:
            if first and started: by += 4
            started = True
            e(f'<text class="pain" x="{x + 2:g}" y="{by:g}">{runs(l, {"pb": " font-weight=\"700\""})}</text>'); by += BUL_LH

for i, s in enumerate(STEPS):
    if not s.get("note"): continue
    x, y = box_xy(i, s); nw = TASK_W - 10
    nx = (x - COL_W + 24) if s.get("note_side") == "left" else (x + COL_W + 14)
    lines = wrap_words([(w, "n") for w in s["note"].split()], 22)
    nh = 34 + len(lines) * 17 + 12; ny = y + 4
    e(f'<g><rect x="{nx + 3:g}" y="{ny + 4:g}" width="{nw}" height="{nh}" fill="#000" opacity=".12"/>'
      f'<path d="M {nx:g} {ny:g} H {nx + nw:g} V {ny + nh - 16:g} L {nx + nw - 16:g} {ny + nh:g} H {nx:g} Z" fill="#FFE97A" stroke="#E0C341"/>'
      f'<path d="M {nx + nw:g} {ny + nh - 16:g} H {nx + nw - 16:g} V {ny + nh:g} Z" fill="#E8CF55"/>'
      f'<text class="stk-h" x="{nx + 12:g}" y="{ny + 18:g}">TO CONFIRM</text>')
    ty = ny + 38
    for l in lines:
        e(f'<text class="stk" x="{nx + 12:g}" y="{ty:g}">{html.escape(" ".join(w for w, _ in l))}</text>'); ty += 17
    e('</g>')

for i in range(len(STEPS) - 1):
    a, b = STEPS[i], STEPS[i + 1]
    ax, ay = box_xy(i, a); bx, by_ = box_xy(i + 1, b)
    y1, y2 = ay + TASK_H / 2, by_ + TASK_H / 2; x1, x2 = ax + TASK_W, bx - 3
    if a["li"] == b["li"]:
        e(f'<line class="arr" x1="{x1:g}" y1="{y1:g}" x2="{x2:g}" y2="{y2:g}" marker-end="url(#ah)"/>')
    else:
        mx = ax + BOX_W + PAD_X; r = 12; d = 1 if y2 > y1 else -1
        e(f'<path class="arr" d="M {x1:g} {y1:g} L {mx - r:g} {y1:g} Q {mx:g} {y1:g} {mx:g} {y1 + d*r:g} L {mx:g} {y2 - d*r:g} Q {mx:g} {y2:g} {mx + r:g} {y2:g} L {x2:g} {y2:g}" marker-end="url(#ah)"/>')
e('</svg>')

logo_html = ""
if spec.get("logo"):
    src = spec["logo"]
    if not src.startswith("data:"):
        try:
            from PIL import Image
            im = Image.open(src).convert("RGB"); im.thumbnail((200, 80))
            buf = io.BytesIO(); im.save(buf, "JPEG", quality=75, optimize=True)
            src = "data:image/jpeg;base64," + base64.b64encode(buf.getvalue()).decode()
        except Exception:
            ext = os.path.splitext(src)[1].lstrip(".").lower() or "png"
            src = f"data:image/{ext};base64," + base64.b64encode(open(src, "rb").read()).decode()
    logo_html = f'<img class="logo" alt="{html.escape(spec.get("client", ""))}" src="{src}"/>'

def li(kind, label): return f'<div><svg width="24" height="24" viewBox="0 0 24 24">{icon(kind, 1, 1)}</svg><span>{label}</span></div>'
legend = '<div class="lgbox"><div class="lgt">Legend</div><div class="lgd">' + li("user", "User task") + li("manual", "Manual task") + li("script", "Automated (script)") + '</div></div>'
lane_note = f'<div class="lanenote"><span>TO CONFIRM</span>{html.escape(spec["lane_note"])}</div>\n' if spec.get("lane_note") else ""
```

## add_sticky_lanes.py

Post-processes a rendered (or tab-combined) map. It moves the blue lane rects (width 190, fill #004890) and `text.lane` labels into a group on top of the SVG and shifts that group by the `.map` container's scroll position, so the titles stay pinned. Hidden tabs are skipped until shown. If `LANE_W` or `BLUE` in `render_map.py` ever change, update the selector to match. The client project keeps a copy at `claude/maps/add_sticky_lanes.py`.

```python
#!/usr/bin/env python3
"""Add frozen swimlane titles to a combined map: python3 add_sticky_lanes.py in.html out.html"""
import sys
src, out = sys.argv[1], sys.argv[2]
h = open(src).read()
css = ".lanefix{filter:drop-shadow(3px 0 3px rgba(0,0,0,0))}.lanefix.on{filter:drop-shadow(4px 0 4px rgba(0,0,0,.25))}\n"
js = """<script>
document.querySelectorAll('.map').forEach(m=>{
  const svg=m.querySelector('svg'); if(!svg) return;
  const ns='http://www.w3.org/2000/svg', g=document.createElementNS(ns,'g'); g.setAttribute('class','lanefix');
  [...svg.querySelectorAll('rect[width="190"][fill="#004890"], text.lane')].forEach(el=>g.appendChild(el));
  svg.appendChild(g);
  const vbw=svg.viewBox.baseVal.width;
  const upd=()=>{const w=svg.getBoundingClientRect().width; if(!w) return; const k=vbw/w, x=m.scrollLeft*k;
    g.setAttribute('transform','translate('+x+',0)'); g.classList.toggle('on',m.scrollLeft>2);};
  m.addEventListener('scroll',upd,{passive:true}); window.addEventListener('resize',upd); upd();
});
</script>"""
h = h.replace("</style>", css + "</style>", 1).replace("</body>", js + "</body>", 1)
open(out, "w").write(h); print("ok", out, len(h))
```

## Revising a map

Edit the spec JSON and re-render (then re-run `add_sticky_lanes.py`). Don't hand-edit the HTML. After each change, re-screenshot and check for:

- overlapping stickies or arrows
- crowded START/END text
- awkward line wraps

Keep the spec saved in the client's project so the next session can pick it up.

# Check – transcript audit of the latest process map

An independent, line-by-line audit of a finished map. The goal is to catch anything on the map that a client interviewee did not actually say. Report only. **Never edit the map, the spec or the HTML.** Fran decides what changes.

## 1. Find the most recent map

1. Call `project_info` on the client project and list every doc under `claude/maps/` ending in `_spec.json` (also `*_pending_steps.json` if it is newer and has no spec yet).
2. `project_read` each candidate and compare `created_at`. The newest one is the map to check.
3. If a map name or file was given with the request, use that instead.
4. Tell Fran in one line which map you picked (title, subtitle, tabs if several) before going further. If two maps were created within minutes of each other, or the newest is a combined file built by `combine_tabs.py`, ask which one she means.
5. If the HTML is newer than the spec (SharePoint `3. Clients/<Client>/01. Digital Operations Assessment/4. Deliverables/Process Maps`, or a file Fran attaches), audit the HTML text, since it may contain hand edits.
6. Read any existing cross-check doc for that map (`claude/*CrossCheck.md`) so you know which items were already flagged and accepted.

Break the map into an audit list. One row per checkable claim:
- lane names
- each step title, its lane, its icon kind (user / manual / script) and its software label
- each bullet, including any bold report or file name
- each pain point
- each TO CONFIRM sticky
- each arrow or hand-off between lanes
- the map title and subtitle

## 2. Get every transcript

- Primary source: SharePoint `3. Clients/<Client>/01. Digital Operations Assessment/2. Client Reference Materials/3. Interview Transcripts`. Pull **all** of them, not just the ones the cross-check doc cites.
- Fallback: Circleback (`SearchMeetings` / `GetTranscriptsForMeetings` for the client), or files Fran attaches.
- List the transcripts you found (interviewee, date) and say so if any could not be opened. An audit missing a transcript is incomplete; say that plainly in the report.

## 3. Audit

Split the transcripts across parallel subagents (3–4 transcripts each). Give every subagent the full audit list and these instructions:

- For each audit row, find every passage that supports, contradicts or relates to it. Quote the words and give speaker + timestamp.
- Only a **client interviewee** counts as a source. An Automized interviewer's statement, question, survey read-back or summary is not a source unless the client clearly confirms it in their own words. A bare "yeah" to a leading question is weak support; flag it as such.
- Check context: who the speaker was describing (themselves, another store, another role), whether it was current state or a wish, and whether a "pain point" was actually framed as a complaint.
- Return findings, not opinions about the process.

Then merge the results and classify every row into one of these:

| Category | Meaning |
|---|---|
| **Supported** | A client said it, in this context. Cite it. |
| **Incorrect / false** | A transcript contradicts it (wrong role, wrong software, wrong order, wrong number, wrong name). |
| **Hallucinated** | Nothing in any transcript supports it. |
| **Implied, not stated** | It's an inference, a paraphrase that adds meaning, or a gap filled by Automized (e.g. an assumed hand-off, an assumed owner, "scheduled" when nobody said so). |
| **Wrong source** | Only supported by an interviewer, a survey read-back, a playbook or the D1 inventory, not by a client. |
| **Misattributed** | Said by a client, but about a different role, store, process or time than the map shows. |
| **Overstated** | The idea is real but the map makes it stronger, more general or more certain ("all stores" from one person, a one-off made into a standard step). |
| **Pain point mismatch** | The quote wasn't a complaint, or belongs to a different lane. |
| **Sticky answered** | A TO CONFIRM note that a transcript already answers. Give the answer and cite it. |
| **Missing (in scope)** | Stated in transcripts, belongs on this map, and isn't on it. |
| **Belongs on another map** | Stated, but out of scope for this one. Name the map. |

Also flag any break of the Maps skill content rules, since those are errors too: software named as a lane, a person's name in task text, judgments or assessments, more than 3 bullets, frequency chips, a file name in bold without being stated (and no sticky), or more than one icon.

Be strict. If you can't find support, don't soften it to "probably fine". If a timestamp in the existing cross-check doc doesn't hold up, say so.

## 4. Report

Reply in chat with:

1. One line: which map, how many transcripts checked, and the count per category.
2. A table of every problem row (everything that isn't Supported), grouped by category in the order above: map element | what the map says | what the transcripts say (quote, speaker, timestamp) | suggested fix.
3. Supported rows collapsed to a short count, not listed, unless Fran asks.

Keep wording plain and short. No names of Automized staff as sources.

## 5. Save

Write the full audit (all rows, including Supported with citations) to the client project as `claude/<MapName>_Check_<YYYY-MM-DD>.md` with `project_write`. Don't overwrite the original cross-check doc. Tell Fran the file name, and ask whether she wants any fixes applied with the Maps skill.

# Email

Compose a polished follow-up email from the user's source material and stage it inline in chat with an **Open in Mail** button that hands the draft to the user's default mail app (e.g. Outlook), so the user does the final review and send. Supporting files are referenced as attachments and the user is prompted to attach them — file contents are never embedded in the email body.

## Why this matters

The user wants a ready-to-review draft they can hand to Outlook (or their mail app), not a message that gets auto-sent and not a wall of pasted document content. Mail apps handle real attachments far better than inline HTML or copied text, so the email should *name* the attachments and let the user drag them in. This keeps the body clean and the message professional.

## Workflow

### 1. Gather what you need

Before composing, make sure you have:

- **Source material** — the content the email is based on (a meeting/training summary, transcript, notes, or a reference doc). If the user uploaded files, read them to extract the substance: who was involved, what was covered, decisions made, and action items.
- **Recipient** — who the email is to. If unknown, leave the To field empty and tell the user to add it.
- **Sender** — who it's from (sign-off name). Infer from context/memory if available.
- **Tone** — default to warm-but-professional unless the user specifies otherwise.

If the source material is thin or missing, ask one focused question rather than guessing. Otherwise proceed.

### 2. Compose the email

Write a clean, skimmable follow-up. A reliable structure:

- **Opening line** — thank them / acknowledge the meeting or interaction, one or two sentences, specific to context.
- **Recap** — the key points covered, as a short bulleted list. Keep each bullet to a lead phrase plus a sentence.
- **Action items / next steps** — a short numbered list of what the recipient should do, in priority order.
- **Attachment reference** — explicitly mention the attached file(s) by name and what each is for (see below).
- **Close** — an offer to help further, then the sign-off.

Keep it tight. Pull real specifics from the source material (names, counts, concrete outcomes) so it reads like a genuine recap, not a template. Verify any specific claim against the source rather than inventing detail.

### 3. Reference attachments — do NOT embed file contents

This is the core rule of the skill. When the email is based on or accompanied by files:

- **Name each attachment** in the body and say what it is — e.g., "I've attached today's session summary and the Getting Started playbook for reference."
- **Never paste the file's contents** (HTML, full text, tables) into the email body. The files travel as real attachments, not inline text. `mailto:` links cannot carry file attachments at all — the user must attach them manually in the mail app.
- Use the actual filenames where known so the user knows exactly which files to attach.

### 4. Stage with the Open in Mail button

Render the draft inline in chat using the visualization tool (`mcp__visualize__show_widget`). If this is the first widget call in the session, call `mcp__visualize__read_me` with `modules: ["interactive"]` first.

Build the widget as a small card showing To / Subject / a preview of the body, with a button that opens the user's default mail app.

**Build the mailto URL:**

- `mailto:<recipient-or-empty>?subject=<url-encoded subject>&body=<url-encoded body>`
- URL-encode the subject and body (spaces as `%20`, commas as `%2C`, line breaks as `%0D%0A`, etc.).
- If the recipient is unknown, leave it blank: `mailto:?subject=...&body=...`.

**Known gotcha — use a button + `openLink()`, not a plain link:**

A plain `<a href="mailto:...">` does NOT work inside the chat widget — the widget renders in a sandboxed iframe that only intercepts `http(s)` links, so `mailto:` clicks are silently swallowed. The confirmed working pattern is a `<button>` with a click handler that calls the widget's global `openLink()` function:

```html
<button id="open-mail-btn">Open in Mail</button>
<script>
var mailtoUrl = "mailto:RECIPIENT?subject=SUBJECT&body=BODY";
document.getElementById('open-mail-btn').addEventListener('click', function() {
  if (typeof openLink === 'function') {
    openLink(mailtoUrl);
  } else {
    window.location.href = mailtoUrl;
  }
});
</script>
```

This has been tested and confirmed to successfully open Outlook (or whatever mail app is set as the OS default) with the To, subject, and body pre-filled. Note this depends on the user having a default mail app configured on their OS — if nothing happens when they click, that's a system setting (Windows: Settings > Apps > Default apps > Mail/MAILTO), not a bug in the draft.

### 5. Prompt the user to attach files and fill the recipient

After staging, end with a brief note that does two things:

- Tells the user to **attach the referenced file(s) by name** before sending (list the filenames).
- Reminds them to **add the recipient** in the To field if it wasn't known/included in the mailto link.

Then offer light follow-ups (adjust tone, shorten, split out the recap). Keep this closing note short — the draft is the deliverable.

## Example closing note to the user

> Drafted and ready above — hit **Open in Mail** to drop it into your mail app for review and send.
>
> Two things before you send: attach `summary.docx` and `playbook.pdf` (the email references them), and add the recipient's address in the To field.
>
> Want me to adjust the tone, trim it down, or pull the recap into a shorter note?

## Guardrails

- **Never auto-send.** This skill stages a draft for human review only. The user hits send.
- **Don't fabricate recipients or email addresses.** If you don't know the address, leave it out of the mailto URL and prompt the user.
- **One variant unless the user signals competing goals.** A recap follow-up has one clear job; multiple strategic variants are for higher-stakes messages (negotiation, bad news, pushback).
- **Body stays clean.** No pasted document contents, no inline HTML dumped into the email, no giant quoted blocks — attachments carry the source material.
- **Always use the button + `openLink()` pattern**, never a plain `<a href="mailto:...">`, inside the chat widget.

What these show

  • Accuracy by design. The map skills only allow content a client actually said, and the audit skill checks that independently.
  • Human in the loop. Nothing is auto-sent or silently changed. The analyst reviews and decides.
  • Repeatable quality. Written rules and visual standards mean every map and email comes out the same way, whoever runs the skill.

Client names, people and client systems are replaced with generic labels.
